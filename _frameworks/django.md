web applications.

## 3 Concepts

- Each Django project consists of one or multiple apps
  - Thereby each app encapsulates related business logic
  - Thereby apps can exist independantly of a project and incorporated into projects
    as needed

## 4 Usage

### 4.1 Django CLI

- Django can be managed with the Django CLI

```bash
# create Django project with specified name in current directory
django-admin startproject myproject

# create Django project with specified name in specified directory
django-admin startproject myproject ./mydirectory
```

### 4.2 Management Script

- Existing Django projects can be managed with the `manage.py` script inside the project's
  root directory

```bash
# create Django app with specified name in current Django project
python manage.py startapp myapp

# start local development server for current Django project on port 8000
python manage.py runserver

# generate migration files from the models.py files of the Django apps
python manage.py makemigrations

# apply migration files generated by the makemigrations command
python manage.py migrate

# create superuser for the current Django project (requires migration afterwards)
python manage.py createsuperuser
```

## 5 Project Structure

```text
<project_directory>/  # project root directory
├── <app_name>/       # app directory (may have multiple)
│   ├── migrations/   # migration directory
│   ├── templates/    # template directory
│   ├── admin.py      # admin panel configurations
│   ├── apps.py       #
│   ├── forms.py      # form definitions for templates
│   ├── models.py     # model definitions
│   ├── tests.py      #
│   ├── urls.py       # URL mappings to views
│   └── views.py      # view definitions
├── <project_name>/   # project configuration directory
│   ├── asgi.py       #
│   ├── settings.py   # project settings
│   ├── urls.py       # URL mappings to Django apps
│   └── wsgi.py       #
├── db.sqlite3        # internal data managed by Django (configurable)
└── manage.py         # script to manage the Django project
```

## 6 Settings

- Settings for the entire Django project are defined inside the `settings.py` file of the
  Django project directory
  - This file is pre-populated with default settings
  - The following settings can be applied there:
    - The Django apps to include in the Django project

```python
from pathlib import Path
from typing import Any


# get root directory of the Django project
BASE_DIR: Path = Path(__file__).resolve().parent.parent


# include Django apps in the Django project
INSTALLED_APPS: list[str] = [
    # internal apps to include (populated per default)
    "django.contrib.admin",
    "django.contrib.auth",
    "django.contrib.contenttypes",
    "django.contrib.sessions",
    "django.contrib.messages",
    "django.contrib.staticfiles",

    # user defined apps to include (must be added manually)
    "myapp",
]

# define database connections (elements depend on backend and database type)
DATABASES: dict[str, Any] = {
    # define default database to manage internal data (SQLite per default)
    "default": {
        "ENGINE': "django.db.backends.sqlite3",
        "NAME": BASE_DIR / "db.sqlite3",
    }
}
```

## 7 Views

- Views are mappings of functions or class methods to HTTP requests

```python
from django.http import HttpResponse
from django.shortcuts import render
from django.views import View

from .forms import NameForm


# define view for HTTP request
def index(request) -> HttpRequest:
    # define response to request
    return HttpResponse(content="Hello, World!")


# define view as class
class Hello(View):
    # define method for GET request to view
    def get(self, request) -> HttpResponse:
        return HttpResponse("Hello, World!")


def greet(request) -> HttpResponse:
    # filter for GET request
    if request.method == "GET":

        # access GET request parameter
        if "name" in request.GET:
            print(request.GET.name)

        # render template as response
        return render(
            request=request,             # original request
            template_name="index.html",  # template to render
            context={ "name": "John" },  # pass values to insert into template
        )

    # filter for POST request
    if request.method == "POST":

        # access POST request parameter
        if "name" in request.POST:
            print(request.POST.name)

        # populate form with POST data
        form: NameForm = NameForm(data=request.POST)

        # validate populated form
        if form.is_valid():

            # save form to database when it was derived from a model
            form.save()

            return HttpResponse("Success!")

    return HttpResponse("Not Suported")
```

## 8 Routing

- Routes map specific URLs to defined views
  - Thereby the mapped views are executed when the specified URLs are requested

- Routes are defined inside the `urls.py` files of the Django project and Django apps

- The `urls.py` file of the Django project maps URLs as prefixes to Django apps

```python
from django.contrib import admin
from django.urls import URLPattern, include, path


# map URLs prefixes to app URLs
urlpatterns: list[URLPattern] = [
    path(route="admin/", view=admin.site.urls),      # map URL prefix to internal admin app
    path(route="", view=include(arg="myapp.urls")),  # map URL prefix to all URLs of specified app
]
```

- The `urls.py` files of Django apps map URLs to their views
  - These `urls.py` files have to be created manually

```python
from django.urls import path, URLPattern

from . import views


# map URLs to views
urlpatterns: list[URLPattern] = [
    path(route="hello", view=views.hello),      # map URL to view function
    path(route="hi", view=views.Hi.as_view()),  # map URL to view class
]
```

## 9 Models

- Models are abstractions of database entities managed by Django
  - Thereby database tables are derived automatically from them

- Models are defined in the `models.py` file of the according Django project

- To apply updates to models a migration must be performed (see [4 Usage](#4-usage))

```python
from django.db.models import (
    CharField,
    DateField,
    IntegerChoices,
    IntegerField,
    Model,
)


# define model with automatically managed primary key
class Person(Model):
    # define text element
    name: CharField = CharField(
        max_length=255,  # limit length of text
    )

    # define integer element
    age: IntegerField = IntegerField()

    # define integer choice element
    friends: IntegerChoices = IntegerChoices

    # define datetime element
    registrated_at: DateField = DateField(
        auto_now=True,  # populate with current datetime automatically
    )
```

## 10 Forms

- Forms to generate can be defined in the `forms.py` file of a Django app
  - This file has to be created manually

```python
from django import forms
from django.db.models import Model

from .models import MyModel


# generate form automatically from defined model
class Registration(forms.ModelForm):
    class Meta:
        model: Model = MyModel   # define model to use
        fields: str = "__all__"  # generate a form element for each model element
```

## 11 Templates

- Templates can be defined as HTML files in the `templates` directory of the according
  Django app
  - This directory has to be created manually

- Django uses its own templating language based on Jinja to generate templates
  - This allows the dynamic insertion of values and generation of HTML at runtime

```html
<!DOCTYPE html>

<html lang="en">

    <head>
        <meta charset="UTF-8">
        <meta name="viewport" content="width=device-width, initial-scale=1.0">
        <title>Document</title>
    </head>

    <body>
        <!-- insert value from view into template -->
        <p>Hello, {{ name }}!</p>

        <!-- defin forms in template -->
        <form method="POST">
            {% csrf_token %}  <!-- insert CSRF token for form (required!) -->
            {{ form }}        <!-- insert defined form from forms.py as HTML form elemnts -->
            <button type="submit">Save</button>
        </form>
    </body>

</html>
```

## 12 Administration

- Django provides an admin panel per default in which users, permission groups and
  databases can be managed
  - This panel is reachable at `/admin`
  - To reach that panel at least one superuser must be created and a migration must have been
    performed (see [4 Usage](#4-usage))

- Models must be registered in the `admin.py` file of the according Django app to make them
  accessable in the admin panel

```python
from django.contrib import admin

from .models import MyModel


# register model to admin panel
admin.site.register(model_or_iterable=MyModel)
```
