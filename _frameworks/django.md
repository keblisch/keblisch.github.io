## 3 Concepts

- Each Django project consists of one or more apps
  - Each app encapsulates related functionality
  - Apps can exist independently of a project and be incorporated into projects
    as needed

## 4 Usage

### 4.1 Django CLI

- Django can be managed with the Django CLI

```bash
# create Django project with specified name in current directory
django-admin startproject myproject

# create Django project with specified name in specified directory
django-admin startproject myproject ./mydirectory
```

### 4.2 Management Script

- Existing Django projects can be managed with the `manage.py` script inside the project's
  root directory

```bash
# create Django app with specified name in current Django project
python manage.py startapp myapp

# start local development server for current Django project on port 8000
python manage.py runserver

# generate migration files from the models.py files of the Django apps
python manage.py makemigrations

# apply migration files generated by the makemigrations command
python manage.py migrate

# create superuser for the current Django project (requires migrations beforehand)
python manage.py createsuperuser
```

## 5 Project Structure

```text
<project_directory>/  # project root directory
├── <app_name>/       # app directory (may have multiple)
│   ├── migrations/   # migration directory
│   ├── templates/    # template directory
│   ├── admin.py      # admin panel configurations
│   ├── apps.py       #
│   ├── forms.py      # form definitions for templates
│   ├── models.py     # model definitions
│   ├── tests.py      #
│   ├── urls.py       # URL mappings to views
│   └── views.py      # view definitions
├── <project_name>/   # project configuration directory
│   ├── asgi.py       #
│   ├── settings.py   # project settings
│   ├── urls.py       # URL mappings to Django apps
│   └── wsgi.py       #
├── db.sqlite3        # internal data managed by Django (configurable)
└── manage.py         # script to manage the Django project
```

## 6 Settings

- Settings for the entire Django project are defined in the `settings.py` file of the
  Django project directory
  - This file is pre-populated with default settings
  - The following settings can be applied there:
    - The Django apps to include in the Django project
    - The databases to use

```python
from pathlib import Path
from typing import Any


# get root directory of the Django project
BASE_DIR: Path = Path(__file__).resolve().parent.parent


# include Django apps in the Django project
INSTALLED_APPS: list[str] = [
    # internal apps to include (populated per default)
    "django.contrib.admin",
    "django.contrib.auth",
    "django.contrib.contenttypes",
    "django.contrib.sessions",
    "django.contrib.messages",
    "django.contrib.staticfiles",

    # user defined apps to include (must be added manually)
    "myapp",
]


# define database connections (elements depend on backend and database type)
DATABASES: dict[str, Any] = {
    # define default database (SQLite per default)
    "default": {
        "ENGINE": "django.db.backends.sqlite3",
        "NAME": BASE_DIR / "db.sqlite3",
    }
}
```

## 7 Views

- Views are functions or classes that process HTTP requests and return responses

```python
from django.http import HttpRequest, HttpResponse
from django.shortcuts import render
from django.views import View

from .forms import NameForm


# define a view for an HTTP request
def index(request: HttpRequest) -> HttpResponse:

    # define the response to the request
    return HttpResponse(content="Hello, World!")


# define a view as a class
class Hello(View):

    # define the method for GET requests to the view
    def get(self, request) -> HttpResponse:
        return HttpResponse("Hello, World!")

    # define the method for POST requests to the view
    def post(self, request) -> HttpResponse:
        return HttpResponse("Success!")


def greet(request) -> HttpResponse:
    # handle GET requests
    if request.method == "GET":

        # access GET request parameter
        if "name" in request.GET:
            print(request.GET["name"])

        # render a template as the response
        return render(
            request=request,             # original request
            template_name="index.html",  # template to render
            context={"name": "John"},    # pass values to insert into template
        )

    # handle POST requests
    if request.method == "POST":

        # access POST request parameter
        if "name" in request.POST:
            print(request.POST["name"])

        # populate form with POST data
        form: NameForm = NameForm(data=request.POST)

        # validate populated form
        if form.is_valid():

            # save form to database when it was derived from a model
            form.save()

            return HttpResponse("Success!")

    return HttpResponse("Not Supported")
```

## 8 Routing

- Routes map specific URLs to defined views
  - The mapped views are executed when the specified URLs are requested

- Routes are defined in the `urls.py` files of the Django project and Django apps

- The `urls.py` file of the Django project maps URL prefixes to Django apps

```python
from django.contrib import admin
from django.urls import URLPattern, include, path


# map URL prefixes to app URLs
urlpatterns: list[URLPattern] = [
    # map the URL prefix to the internal admin app
    path(route="admin/", view=admin.site.urls),

    # map the URL prefix to all URLs of the specified app
    path(route="", view=include(arg="myapp.urls")),
]
```

- The `urls.py` files of Django apps map URLs to their views
  - These `urls.py` files must be created manually

```python
from django.urls import path, URLPattern

from . import views


# map URLs to views
urlpatterns: list[URLPattern] = [
    # map URL to view function
    path(
        route="hello",     # URL path
        view=views.hello,  # view function
        name="hello",      # internal mapping name for templates
    ),

    # map URL to view class
    path(
        route="hi",               # URL path
        view=views.Hi.as_view(),  # view class
        name="hi",                # internal mapping name for templates
    ),
]
```

## 9 Models

- Models are abstractions of database entities managed by Django
  - Database tables are derived automatically from them

- Models are defined in the `models.py` file of the corresponding Django app

- To apply updates to models, migrations must be created and applied (see [4 Usage](#4-usage))

```python
from django.db.models import (
    CharField,
    DateField,
    IntegerChoices,
    IntegerField,
    Model,
)


# define a model with an automatically managed primary key
class Person(Model):
    # define a text field
    name: CharField = CharField(
        max_length=255,  # limit the length of the text
    )

    # define an integer field
    age: IntegerField = IntegerField()

    # define integer choice element
    friends: IntegerChoices = IntegerChoices()

    # define a date field
    registered_at: DateField = DateField(
        auto_now=True,  # populate with the current date automatically
    )

    # define the string representation (used by the admin panel)
    def __str__(self) -> str:
        return self.name
```

- Models can be used to access and manipulate their represented database entries

```python
from django.db.models import QuerySet

from .models import MyModel


# query the database for all entities of the specified model
result: QuerySet[MyModel] = MyModel.objects.all()
```

## 10 Forms

- Forms can be defined in the `forms.py` file of a Django app
  - This file has to be created manually

```python
from django import forms
from django.db.models import Model

from .models import MyModel


# generate a form automatically from the defined model
class Registration(forms.ModelForm):
    class Meta:
        model: Model = MyModel   # define the model to use
        fields: str = "__all__"  # generate a form field for each model field
```

## 11 Templates

- Templates can be defined as HTML files in the `templates` directory of the corresponding
  Django app
  - This directory has to be created manually

- Django uses its own templating language, the Django Template Language (DTL), to render templates
  - This allows dynamic insertion of values and generation of HTML at runtime

```html
<!DOCTYPE html>

<html lang="en">

    <head>
        <meta charset="UTF-8">
        <meta name="viewport" content="width=device-width, initial-scale=1.0">
        <title>Document</title>
    </head>

    <body>
        <!-- insert value from view into template -->
        <p>Hello, {{ name }}!</p>

        <!-- insert element of dictionary from view into template -->
        <p>Hello, {{ person.name }}!</p>

        <!-- loop over list or set from view and generate HTML with each iteration -->
        {% for my_item in my_inserted_object %}
            <!-- access element of current iteration -->
            <p>{{ my_item.name }}</p>
        {% endfor %}

        <!-- define form in template -->
        <form method="POST">
            {% csrf_token %}  <!-- insert CSRF token for form (required!) -->
            {{ form }}        <!-- insert defined form from forms.py as an HTML form element -->
            <button type="submit">Save</button>
        </form>
    </body>

</html>
```

- Django templates can be inserted into other templates

`base.html`:

```html
<!DOCTYPE html>

<html lang="en">

    <head>
        <meta charset="UTF-8">
        <meta name="viewport" content="width=device-width, initial-scale=1.0">
        <title>Document</title>
    </head>

    <body>
        <!-- define block in which templates can be inserted -->
        {% block my_insertion %}
        {% endblock %}
    </body>

</html>
```

`insert.html`:

```html
<!-- define template in which to insert -->
{% extends "base.html" %}

<!-- define block of template in which to insert -->
{% block my_insertion %}
<p>
    This is my dynamically inserted HTML!
</p>
{% endblock %}
```

## 12 Administration

- Django provides an admin panel by default in which users, permission groups, and
  databases can be managed
  - This panel is reachable at `/admin/`
  - To access the panel, at least one superuser must be created, and migrations must have been
    performed (see [4 Usage](#4-usage))

- Models must be registered in the `admin.py` file of the corresponding Django app to make them
  accessible in the admin panel

```python
from django.contrib import admin

from .models import MyModel


# register the model in the admin panel
admin.site.register(model_or_iterable=MyModel)
```
